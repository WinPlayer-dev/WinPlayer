# 国际化（i18n）约定

> 本文是**写文案的唯一依据**。新增界面、改文案、加语种之前先读完它。
> 运行时实现见 `src/i18n/index.ts`，词条见 `src/i18n/locales/`。

## 1. 为什么不用 vue-i18n

- 本项目有三类前端入口（主窗口 `appMain.ts`、桌面歌词窗口 `desktopLyricsMain.ts`、
  主题预览脚手架 `theme-preview/*-main.ts`），它们各自 `createApp`。走
  `app.config.globalProperties.$t` 就得每个入口装一次，漏一个就是「模板里 $t 未定义」。
- vue-i18n 默认在运行时编译消息，内部用 `new Function`。Tauri 一旦收紧 CSP
  （`script-src` 不含 `'unsafe-eval'`），整站文案会直接空白。要避开就得再加
  `@intlify/unplugin-vue-i18n` 做预编译。
- 本项目只有中文一种基准语种，将来最多加一两种，**用不到复数规则与消息编译器**。
  真正要的是「key 写错能在编译期报错」——这靠 TS 类型就够了。

所以：**词条是普通 TS 对象，`t()` 是个纯函数，零依赖、零构建插件、零 CSP 风险。**

并在上表补一行。

## 3. 三种用法

### 组件（99% 的情况）

```vue
<script setup lang="ts">
import { useI18n } from "@/i18n";

const { t } = useI18n();
</script>

<template>
  <button>{{ t("common.action.confirm") }}</button>
  <p>{{ t("library.playlist.trackCount", { count: 12 }) }}</p>
</template>
```

`t()` 内部会读一次 `locale` ref，所以这个调用发生在渲染里 → 切语言自动重渲染。

### 非组件 TS（service / store）

```ts
import { t } from "@/i18n";

throw new Error(t("errors.download.dirUnavailable"));
```

服务层基本只在**抛错 / 生成 toast 文案**时用；实在要在 `computed` 外缓存，
必须包 `computed(() => t(...))`，否则是快照。

### store / service 不放界面文案

选项数组只放**代码值**，显示名由消费方按值取词条：

```ts
// services/lyricStyle.ts —— 对
export const LYRIC_FONT_OPTIONS: readonly LyricFontPreset[] = ["default", "sans", "serif"];

// stores/settings.ts —— 对
export const STARTUP_PAGE_OPTIONS = [{ value: "recommend", route: "recommend" }];
```

```ts
// 错：数据层塞了 label，切语言要重建整个数组，而且文案有了两份来源
export const OPTIONS = [{ value: "recommend", label: "推荐" }];
```

迁移时已按这个口径清理过 `StartupPageOption.label`、`AUTO_PLAYLIST_LANGUAGES.label`、
`LYRIC_EASINGS.label`、`LYRIC_FONT_OPTIONS.label` —— **别再塞回去**。

例外只有一个：`src/i18n/index.ts` 的 `LOCALES[].label`（语种自称，本身就不翻译）。

### 动态 key（能不用就不用）

```ts
import { tDynamic } from "@/i18n";

// key 由运行时拼出来，拿不到编译期校验
tDynamic(`settings.category.${key}`);
```

优先级：把结构写进词条（`settings.category.general` / `.appearance` …）让 key 是字面量
> `tDynamic` 拼字符串。

## 4. 命名规范

| 规则 | 正例 | 反例 |
| --- | --- | --- |
| 分组 → 元素，点分到底 | `settings.general.title` | `settings_general_title` |
| 叶子用 camelCase | `common.action.restoreDefault` | `common.action.restore-default` |
| key 描述**含义**不描述文案 | `common.action.delete` | `common.action.shanchu` / `common.action.btnRed2` |
| 同一动作全站一个词条 | 复用 `common.action.delete` | 每页各写一遍「删除」 |
| 带变量用 `{name}` 全名占位 | `{count}`、`{keyword}` | `{n}`、`{0}` |
| 词条值不带句号、不带「请」 | `删除` / `确定要删除吗？` | `请您删除。` |

**别按页面复制词条。** 同一个「取消」在十二个页面里都写一遍，
将来加英文要改十二处，而且很容易改漏成两种译法。

## 5. 什么该翻、什么不该翻

**要翻**（用户可见的文案）：

- 模板里的文本节点、`title` / `placeholder` / `label` / `aria-label` / `alt`
- `toast` / `dialog` / 右键菜单 / 空态 / 错误提示
- 下拉选项、开关的说明文字、搜索索引里的标题与关键词
- `<title>`、页面大标题

**不翻**：

- 代码注释（本项目注释是中文，**迁移时绝对不要动**）
- `console.*` 日志、`throw new Error("...")` 里的开发期文案
- SQL、正则、CSS 类名、`data-*`、`ref` key、插件 id
- 用户数据：歌曲名、歌手名、歌单名、文件路径
- 插件 manifest 里的显示名与描述（属于插件作者，宿主不翻译）
- 服务端 / Rust 返回的错误原文

## 6. 插值、复数、格式化

插值用 `{name}`：

```ts
// zh-CN/library.ts
playlist: { trackCount: "{count} 首歌曲" }

// 组件
t("library.playlist.trackCount", { count: 12 })  // → "12 首歌曲"
```

**没有复数规则**。中文不需要；将来接英文时，数量词各写一条即可
（`oneTrack` / `nTracks`），由调用方按数值选——比引入 ICU 复数语法轻得多。

数字与日期走 `Intl`（已按当前语种缓存实例）：

```ts
import { n, d } from "@/i18n";

n(12345.6, { maximumFractionDigits: 1 })   // zh-CN → "12,345.6"
d(Date.now(), { dateStyle: "medium" })     // zh-CN → "2026年11月11日"
```

时长格式化（`mm:ss`）**不是** i18n 的事，继续用原来的工具函数。

## 7. 迁移一条文案的标准动作

1. 在对应域文件里加词条（先搜索有没有可复用的通用词条）。
2. 组件里 `const { t } = useI18n()`（已有就跳过）。
3. 把字面量换成 `t("...")`。**保留原有的标签、类名、v-if 结构**，只替换文本。
4. 带 `{{ }}` 的表达式、`:prop="cond ? 'A' : 'B'"` 这类分支文案也要换。
5. 跑 `npm run i18n:scan`，确认这个文件的计数下降；跑 `npm run typecheck`。

**只改文案，不改逻辑。** 迁移 diff 里出现行为变化就是搞错了。

### 设置页的两个特殊之处

1. **索引引用 key，不抄文案。** `views/settings/settingsIndex.ts` 的
   `SETTINGS_SECTIONS` / `SETTINGS_ITEMS` 存的是 `titleKey` / `descriptionKey`，
   与面板模板的 `.card-header` / `.card-description` 指向同一个 key。取文本用
   `sectionTitle()` / `itemTitle()` / `itemDescription()`。
2. **搜索摘要单独一份。** 索引里的 `descriptionKey` 往往指向
   `settings/searchHints.ts`：那句摘要是「你为什么搜得到它」（同义词、场景），
   与卡片描述「这个开关做什么」内容不同，有意分开。新增设置项时按
   `<分类>.<条目 id 去掉分类段后转小驼峰>` 补一条。

### 词条重复的处理

单字名词（歌单 / 歌手 / 专辑）在不同位置可以各自成词条——英文里
「Recommend」（导航）与「Recommended」（推荐项）本来就该分开译。
但**同一个短语**在多个文件里各写一份是浪费，评审时优先合并：

- 动作目录类（快捷键、播放模式、音质）有唯一真源，别在各页面重抄
  （见 `shortcuts.ts`、`types/player.ts` 的 `PLAY_MODE_LABEL`）。
- `npm run i18n:unused` 查「定义了没人用」的死条目，迁移完务必跑一次。

## 8. 新增语种

1. 复制 `locales/zh-CN/` 为 `locales/en-US/`，逐条翻译（**不要**用简繁/机翻脚本
   批量生成后不管——界面用词差异很大，比如「设置/設定」「默认/預設」「保存/儲存」）。
2. 用类型约束补齐：

   ```ts
   // src/i18n/locales/en-US/index.ts
   import type { LocaleMessages } from "../zh-CN";
   const enUS: LocaleMessages = { /* ... */ };  // 少一个 key 就编译报错
   export default enUS;
   ```

3. `src/i18n/index.ts` 的 `MESSAGES` 里注册，`LOCALES` 里加一项（`label` 用
   该语言自己的写法，不翻译）。
4. 设置 → 通用 → 语言 会自动出现这个选项（下拉读的是 `LOCALES`）。

主题包（`src/themes/*`）是运行时编译的，`import` 走 `services/themeModules.ts` 的白名单，
其中已包含 `@/i18n`；主题里直接 `import { useI18n } from "@/i18n"` 即可。

## 9. 工具

| 命令 | 作用 |
| --- | --- |
| `npm run i18n:scan` | 统计剩余硬编码中文（按文件排名），迁移进度表 |
| `npm run i18n:scan -- --json` | 明细写入 `.workbuddy/i18n-report.json` |
| `npm run i18n:check` | 有硬编码中文就退出码 1，用于防回归 |
| `npm run i18n:unused` | 找出没有任何引用的词条（死条目），明细写 `.workbuddy/i18n-dead-keys.txt` |

扫描器只看**用户可见**位置：`.vue` 只扫 `<template>` 的文本节点与白名单属性，
`.ts` / `<script>` 先剥注释再找中文字面量，并跳过日志、正则、SQL。
它**宁可漏报不误报**——所以别把它当成唯一防线，评审时还是要看。

自动豁免的情形：`console.*` 日志、正则 / SQL / 超长字面量、
`aliases` 与 `keywords`（搜索同义词属于匹配数据）、与原生错误做字符串比较的
`.includes("…")`、纯占位符（`{歌曲名}`）。整文件豁免在文件头 30 行内写
`i18n-ignore-file`（例：`services/autoPlaylist.ts` 的 Vocaloid 词表）。

扫描器不覆盖的位置（有意为之）：`src/i18n/`（词条本身就是中文）、
`src/plugin-runtime/`（插件沙箱里的第三方代码）、`src/theme-preview/` 与
`src/winui-preview/`（本地截图走查的脚手架，宿主桩 + 假数据，不进生产包）。

当前状态：硬编码 **0 处**，`i18n:check` 可以接进 CI / `prebuild`。

### 界面走查（静态扫描管不到的那部分）

扫描器只看源码，看不出「`t()` 的 key 拼错导致页面上直接显示 key 原文」或「文案变长把布局挤坏」。
补一个运行时走查：

```bash
npx vite --port 5174
node .workbuddy/preview/shoot-i18n-tabs.mjs      # 桌面：8 个分类逐页截图 + 审计
node .workbuddy/preview/shoot-i18n-mobile.mjs    # 手机：UA + 7 个分类（无快捷键）
node .workbuddy/preview/shoot-i18n-search.mjs    # 设置搜索命中与跳转
node .workbuddy/preview/shoot-theme-shell.mjs    # 内置 MD3 主题编译（白名单含 @/i18n）
```

页面入口是 `.workbuddy/preview/i18n-check-preview.html` + `src/theme-preview/i18n-check-main.ts`：
真实挂载 `SettingsView`，只把 Tauri 宿主换成 `theme-preview/harness.ts` 的桩，
并暴露 `window.__i18nAudit()` —— 遍历 DOM 文本节点与 `placeholder` / `title` / `aria-label`
等属性，把形如 `settings.shell.title` 的**未翻译 key 原文**捞出来。

判定标准：每个分类 `rawKeys` 与 `rawAttrKeys` 都是 0，且文本节点数不为 0（为零说明整块没渲染）。
截图落在 `.workbuddy/preview/i18n-*.png`，改完文案用来肉眼比对布局。

> 走查页与脚本都在 `.workbuddy/`（不进仓库），`src/theme-preview/` 下的入口在扫描器的
> 豁免名单里（`.vue` 模板里的中文桩数据不算漏翻）。

## 10. 已知边界

- **`setup` 顶层常量里的文案不会跟着切语言**。比如
  `const FREQUENCIES = [{ value: "startup", label: t("…") }]` 在 `setup` 里只求值一次。
  当前只有 zh-CN 一个语种，这不影响任何用户；等真加了第二语言，这类常量要改成
  `computed(() => [...])`（并同步改调用点为 `.value`）。迁移时**不要**顺手改这个结构——
  那会把「文案替换」变成「行为改动」，评审时看不出来。
- **Rust 侧未接入**：托盘菜单、文件对话框标题、原生错误消息仍是中文。
  切到英文后会出现「英文界面 + 中文报错」的混合态。要彻底解决得把 Rust 命令改成
  返回错误码、由前端翻译，并把当前语种传给托盘重建。
- **插件协议未接入**：manifest 的 `name` / `description` 是单字符串，
  多语言需要改协议（`{ "zh-CN": "...", "en-US": "..." }`）并兼容旧写法。
- **服务端**（WinPlayer-Server）消息原样透传。
- 桌面歌词窗口是独立的 `createApp`，**没有** Pinia / 数据库，它读的是 i18n 模块的
  默认语种；要跟随设置需要主窗口把语种通过 `desktop-lyrics:state` 推过去。
